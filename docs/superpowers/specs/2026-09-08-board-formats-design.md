# Форматы досок — дизайн

Дата: 2026-09-08. Статус: одобрено в чате, реализуется.

## Зачем

Сайт продвигает форматы ретро (`/formats/*`), а продукт умеет только одну доску
«Прошло хорошо / Не получилось / Улучшить». Человек читает про Sailboat, жмёт
«Создать доску» и получает не то, о чём читал. Форматы закрывают этот разрыв и
превращают SEO-страницы в воронку: с каждой страницы формата — кнопка «Создать
доску в этом формате».

## Решения (зафиксированы с пользователем)

- **Только пресеты.** Никаких произвольных колонок. Реестр форматов — в коде.
- **Формат выбирается при создании и больше не меняется.** У существующей доски
  формат менять нельзя: карточки повисли бы между несовпадающими колонками.
- **Старые доски не ломаем.** Все существующие доски автоматически получают
  формат `classic` с прежними id колонок `went_well / didnt_go_well / improve`.
  Данные карточек не мигрируют, экспорт для них не меняется.
- **Классика — дефолт и выбрана заранее** с бейджем «Рекомендуем для начала»,
  чтобы новичок не упирался в терминологию: кнопка «Создать» работает сразу.
- **Память выбора без аккаунтов.** Последний выбранный формат — в localStorage
  браузера (как имя и тема). Пространство запоминает формат последней созданной
  в нём доски и предлагает его при создании следующей. Приоритет предвыбора:
  `?format=` в URL → формат пространства (если создаём внутри него) →
  localStorage → `classic`.

## Реестр форматов

`board-formats.js` в корне репозитория (рядом с `seo-paths.js`, по той же
причине: `server.js` работает в рантайм-образе без `src/`; добавить в COPY
Dockerfile). `src/lib/formats.ts` реэкспортирует его с типами.

```js
{ id: 'classic', columns: [
    { id: 'went_well',     tone: 'well',    title: {en:'Went Well',     ru:'Прошло хорошо'}, short: {en:'Good',    ru:'Хорошо'} },
    { id: 'didnt_go_well', tone: 'bad',     title: {en:"Didn't Go Well",ru:'Не получилось'}, short: {en:'Bad',     ru:'Плохо'} },
    { id: 'improve',       tone: 'improve', title: {en:'To Improve',    ru:'Улучшить'},      short: {en:'Improve', ru:'Улучшить'} } ] }
```

Id формата = slug SEO-страницы (`start-stop-continue`, `mad-sad-glad`, `4l`,
`sailboat`), чтобы `/new?format=<slug>` и ссылки со страниц форматов совпадали
без таблицы соответствий. Названия колонок берём из `content/formats.ts`
(они уже есть парами en/ru); `classic` — из текущих словарных строк.

`tone` — семантический цвет колонки: `well | bad | improve | accent`. Четвёртый
тон (`accent`) нужен четырёхколоночным форматам; палитра accent уже есть.

Колонки форматов:

| формат | колонки (id) | тона |
|---|---|---|
| classic | went_well, didnt_go_well, improve | well, bad, improve |
| start-stop-continue | start, stop, continue | improve, bad, well |
| mad-sad-glad | mad, sad, glad | bad, improve, well |
| 4l | liked, learned, lacked, longed | well, improve, bad, accent |
| sailboat | wind, anchors, rocks, island | well, bad, improve, accent |

## Данные

Миграция `drizzle/0005_board_formats.sql` (ручная, как 0001–0004):

1. `cards.column_type`: enum → `text` (`USING column_type::text`), enum-тип
   удаляется. Значения у старых карточек не меняются.
2. `boards.format text NOT NULL DEFAULT 'classic'`.
3. `spaces.last_format text NULL`.

Схема дублируется в `server.js` — обновить обе копии (`schema.ts` и `server.js`).

## Сервер

- `card:create` и `card:update` с колонкой: колонка обязана принадлежать формату
  доски (лукап доски по `boardId` / по карточке). Чужая колонка — молча игнор,
  как сейчас с невалидным enum.
- `board:state` и загрузка страницы доски отдают `board.format`.
- Создание доски (`/new`, пространство): `format` из формы, валидируется по
  реестру, иначе `classic`. При создании внутри пространства — обновляем
  `spaces.last_format`.
- Экспорт: колонки — по порядку формата доски, ключи JSON — id колонок,
  заголовки Markdown — названия колонок на языке `?lang`. JSON получает
  `board.format`. Для `classic` результат байт-в-байт прежний.

## Клиент

- `Board.svelte`: колонки из `boardStore.format`; сетка `md:grid-cols-2
  xl:grid-cols-N` для четырёх колонок, `md:grid-cols-3` для трёх. Мобильные
  вкладки — из `short`.
- `Column.svelte`, `Card.svelte` (перенос), `Summary.svelte` (бейджи, порядок),
  `boardStore.getSummaryCards` — названия, цвета и порядок из реестра по тону.
- `/new`: блок «Формат» под названием доски — карточки-переключатели
  (название, цветные полоски колонок как в существующем выборе «Доска /
  Пространство», одна строка описания, ссылка «Подробнее» на `/formats/<slug>`
  для не-классики). `classic` — первый, предвыбран, с бейджем.
  При отправке формат пишется в localStorage `retro_format`.
- Модалка создания доски в пространстве (`NewBoardModal.svelte`): компактный
  селект формата с тем же предвыбором.
- Страницы форматов и `/formats`: CTA ведёт на `/new?format=<slug>`.
- Документация API: `board.format` и «ключи `columns` зависят от формата».
- Changelog: запись для пользователей.

## Что не делаем

- Смена формата у созданной доски.
- Произвольные колонки.
- Настройка формата по умолчанию у пространства через UI — пространство просто
  запоминает последний выбор.
- Мудбар на плитках пространства (доли well/bad/improve) для не-классических
  досок остаётся пустым — показывается только число карточек. Отдельная задача.

## Тесты

- Юнит: реестр (уникальные id, у каждого SEO-формата есть доска-формат,
  `classic` сохраняет прежние id), `isValidColumn(format, id)`, экспорт с
  форматом (для `classic` — прежний вывод; для `sailboat` — ключи колонок и
  заголовки Markdown), `getSummaryCards` уважает порядок формата.
- E2e: создание доски через `/new?format=sailboat` → заголовки колонок
  Wind/Anchors/Rocks/Island, карточка добавляется, drag&drop работает, экспорт
  JSON содержит `board.format` и ключ `wind`; существующие спеки (классика)
  остаются зелёными без правок.
