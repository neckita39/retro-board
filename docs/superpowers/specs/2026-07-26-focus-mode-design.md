# Режим фокусировки на обсуждении

Дата: 2026-07-26. Статус: дизайн согласован с пользователем (синхронизация: общая, ведёт создатель ✓; место: секция «Итоги» ✓; подача: подсветка на странице без нового контекста ✓; таймер: отдельный, автостарт 5 минут ✓; навигация: «Далее» + свободный клик, ноль не переключает ✓; пройденные: галочка на время сессии ✓; приглушение остальных: мягкое ✓).

## Цель

Дать ведущему ретро способ собрать внимание всей команды на одной карточке за раз и пройти повестку сверху вниз, не давая обсуждению растекаться. Повестка уже существует — секция «Итоги» (`Summary.svelte`) отдаёт карточки в нужном порядке: сначала «Что прошло хорошо», потом «Что прошло плохо», потом «Что улучшить», внутри каждой колонки — по числу лайков. Фичи не хватает только одной: чтобы у всех участников одновременно подсвечивалась та карточка, которую обсуждают сейчас, и чтобы рядом тикали пять минут.

Ключевое ограничение из обсуждения: **это подсветка на существующей странице, а не новый экран**. Никаких модалок, оверлеев и режимов презентации — «Итоги» остаются на месте и остаются рабочими.

## Пользовательский сценарий

1. Создатель доски видит в шапке секции «Итоги» кнопку **«Обсудить»**.
2. Клик → фокус встаёт на первую карточку текущего порядка и разлетается всем участникам комнаты.
3. У каждого: остальные строки списка мягко гаснут, текущая карточка приподнимается акцентной рамкой, страница плавно доезжает до неё.
4. Рядом с карточкой — таймер `05:00`. Он стартует заново автоматически на каждой новой карточке. На нуле краснеет и пульсирует, но фокус **не** переключает.
5. Наведение (или клавиатурный фокус) на таймер показывает максиму: «Любой спор, который не удаётся завершить за 5 минут, не может быть решён обсуждением».
6. Ведущий жмёт «Далее →» / «← Назад» на самой карточке либо кликает по любой строке списка и прыгает куда хочет. Пройденные карточки получают галочку вместо счётчика лайков — у всех.
7. **«Закончить обсуждение»** в шапке «Итогов» снимает фокус у всей комнаты.

Голосовать и комментировать во время обсуждения можно как обычно — фокус ничего не блокирует.

## Решения

- **Общее состояние, а не локальное.** Смысл фичи — чтобы все смотрели в одну точку; локальный режим чтения этой задачи не решает.
- **Права как у таймера.** Управляет только создатель (`roomCreatorTokens`), остальные — наблюдатели. Иначе на живой ретро начинается война за пульт.
- **Состояние в памяти комнаты, не в БД.** Тот же паттерн, что `roomTimers`: обсуждение — это событие встречи, а не свойство доски. Перезапуск сервера или опустевшая комната сбрасывают фокус, и это правильное поведение.
- **Отдельный таймер обсуждения**, а не переиспользование таймера доски. Таймер в шапке — про другое (таймбокс на написание карточек), и во время обсуждения он должен оставаться доступным. Дублирующий чип в шапке был бы путаницей.
- **Пять минут зашиты константой**, без настройки. В этом и смысл правила из тултипа.
- **Ноль на таймере ничего не переключает.** Таймер сигналит людям, а не рулит встречей; автопереход резал бы говорящего на полуслове и отнимал у ведущего контроль.
- **Фокус привязан к id карточки, а не к позиции.** Во время обсуждения прилетают новые голоса и порядок едет — фокус должен оставаться на той же карточке.
- **Галочки живут в памяти комнаты.** Свободные прыжки кликом сделали линейную позицию недостаточной: без отметок ведущий теряет, что уже прошли. В БД не пишем — вопрос «как снять галочку» не стоит того.
- **Кнопка «Обсудить» всегда видна создателю**, но неактивна при пустых «Итогах» (принцип «не прячем элементы UI по количеству данных»).
- **Тултип кастомный, а не нативный `title`.** В шапке доски конвенция на `title`, но здесь текст длинный и смысловой: нативный всплывает с секундной задержкой и не существует на тач-устройствах.

## Серверная часть (`server.js`)

Состояние комнаты рядом с `roomTimers`:

```js
const roomFocus = new Map(); // slug -> { cardId, endTime, duration, discussed: Set<string> }
```

`FOCUS_DURATION = 300` (секунд) — константа модуля.

| Событие (вход) | Кто | Действие |
| --- | --- | --- |
| `focus:start { cardId, creatorToken }` | создатель | `{ cardId, endTime: Date.now() + 300_000, duration: 300, discussed: new Set([cardId]) }`, broadcast |
| `focus:set { cardId, creatorToken }` | создатель | двигает `cardId`, добавляет в `discussed`, перезапускает отсчёт, broadcast |
| `focus:stop { creatorToken }` | создатель | `roomFocus.delete(slug)`, broadcast с `cardId: null` |

Событие наружу — одно:

```js
io.to(room).emit('focus:state', { cardId, endTime, duration, discussed: [...] })
```

`discussed` уходит массивом (Set не сериализуется через socket.io).

Проверки:
- `if (!currentRoom) return` — как во всех остальных хендлерах.
- Права: `const roomToken = roomCreatorTokens.get(currentRoom) || ''; if (roomToken && creatorToken !== roomToken) return;` — копия таймерной проверки.
- `cardId` — строка длиной 1..64, иначе `return`. Принадлежность карточки доске не проверяем: чужой id просто ничего не подсветит, лишний запрос в БД на каждый переход не нужен.

На `board:join` досылаем текущее состояние, чтобы опоздавший сразу поймал фокус — рядом с существующей досылкой `timer:state`:

```js
const focus = roomFocus.get(slug);
if (focus) socket.emit('focus:state', { ...focus, discussed: [...focus.discussed] });
```

В `disconnect` при `users.size === 0` чистим `roomFocus.delete(currentRoom)` — и заодно `roomTimers.delete(currentRoom)`, который сейчас там не удаляется (соседняя строка, утечка одной записи на комнату).

## Клиентская часть

### `src/lib/stores/socket.svelte.ts` — транспорт

Новые поля состояния: `focusCardId: string | null`, `focusEndTime: number | null`, `focusDuration: number | null`, `focusDiscussed: string[]`.

Новый слушатель `focus:state` раскладывает их по полям. Новые эмиттеры: `startFocus(cardId, creatorToken)`, `setFocus(cardId, creatorToken)`, `stopFocus(creatorToken)`.

Стор остаётся тем, чем был — тонким транспортом без логики.

### `src/lib/focus.ts` — чистая логика навигации

Функции без рун и без сокета, чтобы их можно было тестировать в vitest:

- `focusIndex(cards, cardId): number` — позиция карточки в повестке, `-1` если её нет.
- `nextCardId(cards, cardId, discussed): string | null` — следующая по списку; если текущей карточки в списке уже нет (удалили во время обсуждения) — первая непройденная; в конце списка — `null`.
- `prevCardId(cards, cardId): string | null` — предыдущая; в начале — `null`.

Тип входа — минимальный структурный (`{ id: string }[]`), чтобы функции не тянули за собой доменные типы и легко тестировались.

### Компоненты

- **`FocusTimer.svelte`** — чип `MM:SS` с прогресс-полоской и тултипом с максимой. Отсчёт от `socketStore.focusEndTime` через `setInterval(250)` — тот же приём, что в `Timer.svelte`. На нуле красный + `timer-pulse`. Тултип раскрывается на `hover` и на `focus-visible` (клавиатура), текст — из `focus.maxim`.
- **`SummaryRow.svelte`** — одна строка «Итогов» в трёх состояниях: обычная, сфокусированная (акцентная рамка, приподнята, крупнее, внутри — таймер и кнопки навигации у ведущего), пройденная (галочка вместо счётчика лайков). Выносится из `Summary.svelte`, потому что тот сейчас 70 строк и с фокусом распухнет вдвое; строка — самостоятельная единица с понятной границей.
- **`Summary.svelte`** — оркестрация: кнопка «Обсудить» / «Закончить обсуждение» в шапке, мягкое приглушение непросфокусированных строк (`opacity`, с `transition`), автоскролл.

Автоскролл — `$effect` на `socketStore.focusCardId`: элемент строки скроллится в центр вьюпорта, при `prefers-reduced-motion: reduce` — без анимации.

Клик по строке двигает фокус только если ты создатель и обсуждение уже идёт; в остальных случаях строка ведёт себя как раньше (разворачивает комментарии).

### i18n

Новые ключи в **оба** словаря (`en.json`, `ru.json`): `focus.start`, `focus.stop`, `focus.next`, `focus.prev`, `focus.maxim`, `focus.progress` (`"{n} из {total}"`), `focus.discussed`.

## Крайние случаи

| Ситуация | Поведение |
| --- | --- |
| Сфокусированную карточку удалили | Подсветки нет, список выглядит обычным; «Далее» уводит на первую непройденную |
| Голоса изменили порядок повестки | Фокус остаётся на той же карточке, её позиция в списке (и счётчик «N из M») меняется |
| Участник зашёл в середине обсуждения | Ловит `focus:state` в `board:join`, сразу видит подсветку и оставшееся время |
| Реконнект после деплоя | То же — `board:join` переотправляется автоматически (`everConnected`) |
| Не-создатель шлёт `focus:*` | Отбрасывается на сервере |
| Пустые «Итоги» | Кнопка «Обсудить» видна, но неактивна |
| Дошли до конца повестки | «Далее» неактивна; выход — «Закончить обсуждение» |

## Тесты

**Юнит (vitest, `src/lib/focus.test.ts`)** — навигация: далее/назад по повестке, границы списка (первая/последняя), удалённая текущая карточка, пустой список, `focusIndex` для отсутствующего id.

**E2E (Playwright, `e2e/focus.spec.ts`)** — два browser context на одной доске (создатель по cookie, второй контекст — обычный участник):
1. У участника кнопки «Обсудить» нет, у создателя есть.
2. Создатель жмёт «Обсудить» → у обоих подсвечена одна и та же карточка.
3. Создатель жмёт «Далее» → у обоих фокус переехал, предыдущая помечена галочкой.
4. Создатель жмёт «Закончить обсуждение» → у обоих подсветка снята.

## Вне скоупа

- Настройка длительности обсуждения (5 минут — константа по смыслу фичи).
- Сохранение отметки «обсуждено» в БД и попадание её в экспорт.
- Автопереход по истечении таймера.
- Передача роли ведущего другому участнику.
- Фокус на трёхколоночной доске — фича живёт только в «Итогах».
